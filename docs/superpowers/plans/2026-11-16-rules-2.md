# Dream Isles Rules 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn Dream Isles into a Hearthstone-style game on its own board: growing magic, attack-anything combat with hit-back, 12 mechanics, abilities as data, 41 rebalanced cards, a stronger AI, and the screens and effects for all of it.

**Architecture:** The pure rules engine in `core/` keeps its shape (GameState data, Rules validate/apply returning GameEvents) but card abilities move from one `match` on ability ids to `EffectData` resources run by a small effect runner (`core/effects.gd`) and target resolver (`core/targeting.gd`). New pieces are added beside the old ones first (Tasks 1–3), then Task 4 switches over and migrates all card files in one step so the suite stays green after every task. AI, input, playback and effects in `view/` follow the new events.

**Tech Stack:** Godot 4.7.2, GDScript (static typing), headless test runner `tests/run_tests.gd`, Mobile renderer on desktop and Compatibility renderer on the web.

**Spec:** `docs/superpowers/specs/2026-11-16-rules-2-design.md` (read it with this plan; section numbers below refer to it).

## Global Constraints

- Magic: max +1 per turn, cap **8**, refill each turn; "gain magic" lasts this turn only.
- Hand limit **8**; hero HP 25 (max 25); fatigue 2; start hand 5; Star Shard to the second player.
- Creatures: level-1 cost 1–3, level-2 cost 3–5, level-3 cost 6–8; spells and buildings 1–5 (Star Shard 0).
- Card numbers and texts exactly as spec section 6; card text is generated, never stored.
- Names are our own (Guard, Bubble, Dash, Venom, Leech, Flurry, Hidden, Second Wind, Hush, Dream Up, Combo, Spell Power); never use Hearthstone names in game text.
- The rules engine (`core/`, `ai/`) never references view code.
- Timing-bar rates unchanged: hit 15/50/35, 30/50/20, 50/40/10; block 15/30/50%.
- AI Easy random-action chance 25%; Hard beam width 6, at most 1,500 states per decision.
- Desktop look must not change except where this plan adds visuals; the web build (Compatibility renderer) must match desktop (use `view/look/color_space.gdshaderinc` in any new shader that does colour maths).
- Performance: Low quality stays near 60 fps on the user's Intel HD 620 (`--fps-log`).
- Every new third-party asset is CC0 or CC BY and listed in `assets/CREDITS.md`.
- Test commands: one suite `godot --headless --path . --script res://tests/run_tests.gd -- --only=<file or test substring>`; full suite `timeout 900 godot --headless --path . --script res://tests/run_tests.gd`, which must print `Results: N passed, 0 failed`.
- After adding a `class_name` file, run `godot --headless --path . --import` once so the class is registered.

## Review Focus

1. **Dream Up with a small pool or a full hand:** a filter matching fewer than 3 cards offers every match (no duplicates, never empty unless the pool is empty, in which case nothing is offered); a chosen card with 8 in hand is discarded with `card_burned`. Test in Task 3.
2. **AI turns that never end:** zero-cost plays, Flurry and Dream Up must not loop forever; every AI turn ends with END_TURN within `AIRunner.MAX_ACTIONS`. Test in Task 7.
3. **Stale or invalid human attack input:** releasing on a target that died, became Hidden, or after the turn passed must show a toast and change nothing. Test in Task 9.
4. **Game over in the middle of a cascade:** deaths, Second Wind, When-destroyed draws and fatigue in one action produce exactly one `game_over` and nothing after it. Test in Task 4.
5. **Serialising new actions:** ATTACK (`target_lane`, hero = -1) and CHOOSE (`choice`) survive `to_dict`/`from_dict`, so replays (and later online play) stay exact. Test in Task 6.

### Task 2: Card text generator

**Files:**
- Create: `core/card_text.gd`, `tests/test_card_text.gd`

**Interfaces:**
- Consumes: `CardData`, `EffectData`, `Keywords` (Task 1).
- Produces: `class_name CardText` with `static func render(c: CardData) -> String` (plain text), `static func render_bbcode(c: CardData) -> String` (same text with keyword names, "Combo", "Spell Power", "Hush" and "Dream Up" wrapped in `[b]…[/b]`), `static func tooltip(c: CardData) -> String` (one line per mechanic the card uses: `"<Name>: <rule>"`, joined by `\n`; empty if none).

Generation rules (they produce every string in spec section 6):
- Printed keywords first, in `Keywords.ORDER`, each as `"<Name>."`; then `"Spell Power +N."` if `spell_power > 0`.
- Effects in list order. A run of consecutive effects with the same `when` and `combo` gets one prefix: on_play → `"On play: "` for creatures/buildings and none for spells; on_boop `"Boop: "`; on_destroyed `"When destroyed: "`; start_of_turn `"Start of your turn: "`; end_of_turn `"End of your turn: "`; after_damage `"After this damages a creature, "` (phrase starts lower-case); aura none. Combo adds `"Combo: "`, or `"On play, Combo: "` on a creature's on_play.
- An effect with `who = same_target` joins the previous sentence with `" and "` and uses "it". Consecutive auras on `lane_creature` merge into `"The creature in this lane has " + parts.join(" and ")` with parts `"+N ATK"`, `"+N HP"`, keyword name.
- Phrases: damage `"Deal N damage to <x>"` (chosen_creature "a creature", opposing "the opposing creature", enemy_hero "the enemy hero", all_enemy_creatures "all enemy creatures"); heal (self "Heal this creature N", own_hero "Heal your hero N", all_own_creatures "Heal all your creatures N", lane_creature "Heal the creature in this lane N", chosen_own_creature "Heal one of your creatures N"); draw `"Draw a card"`/`"Draw N cards"`; gain_magic `"Gain N magic"`; freeze (opposing "Freeze the opposing creature", chosen_creature "Freeze a creature", all_enemy_creatures "Freeze all enemy creatures", damaged_creature/same_target "freeze it"); hush (opposing "Hush the opposing creature", chosen_creature "Hush a creature"); return_building `"Return the opposing building to its owner's hand"`; move `"Move this creature to one of your empty lanes"`; swap `"Swap two of your creatures between lanes"`; return_from_discard `"Return a creature from your discard pile to your hand"`; dream_up `"Dream Up a <Land name> <card|creature|spell|building>"` (land omitted when `filter_land == -1`); lane_damage_taken `"The creature in this lane takes N less damage from attacks and hit-back (minimum 1)"`; opposing_atk `"The opposing creature has −N ATK (minimum 0)"` (U+2212 minus); buff `"Give <x> +N/+M"`; give_keyword `"Give <x> <Name>"`; destroy `"Destroy <x>"`. Every sentence ends with `"."`; sentences are joined with one space.

    - `keywords_of(s, p, lane) -> Array[StringName]` (printed unless hushed, plus `gained`, plus building `lane_keyword` auras), `has_keyword(s, p, lane, kw) -> bool`, `spell_power(s, p) -> int` (sum over un-hushed creatures).

Bubble: amount > 0 pops it (`bubble_popped`), dealt 0. Venom: dealt > 0 and src creature has venom → `damage` set to effective max HP (`creature_damaged` carries `"venom": true`). Leech: dealt > 0 and src creature has leech → heal src owner's hero by dealt (`leeched {"player","lane","amount"}` then `hero_healed`). Then src creature's `after_damage` effects with `ctx = {"damaged": {"player": p, "lane": lane}}`. Returns dealt.
    - `damage_hero(s, p, amount, ev, src: Dictionary = {}) -> void` (Leech applies when src is a creature).
    - `hush(s, p, lane, ev)` (spec 4.2; `hushed`), `give_keyword(s, p, lane, kw, ev)` (`keyword_gained`; sets `bubble`/`hidden` if those), `buff(s, p, lane, atk, hp, ev)` (`buffed`), `destroy_creature(s, p, lane, ev)`, `offer_dream_up(s, p, filter_kind, filter_land, ev)` (sets `s.phase = CHOOSING`, `s.pending_choice`, `s.pending_player`; `dream_up_offered {"player","cards"}`), `reveal(s, p, lane, ev)` (`revealed`).
    - `resolve_deaths` checks the active player's lanes first, then the other player's (lane order 0–3, spec 3.5), and now runs `on_destroyed` effects for cards with `effects`, then Second Wind: if the dead creature has second_wind and not `second_wind_used`, `enter_creature` again in the same lane with `damage = max-1`, `second_wind_used = true` (`second_wind` event). Old `trigger` path stays for cards without effects. It stops at once when a hero reaches 0.
    - `effective_attack`/`effective_max_hp` also add `atk_bonus`/`hp_bonus` and new auras (`lane_atk`, `lane_hp`, `opposing_atk`); `damage_reduction(s, p, lane) -> int` sums `lane_damage_taken` (old `has_ice_wall` stays until Task 4).
  - `GameState.Phase` gains `CHOOSING`; `GameState.pending_choice: Array[CardData]`, `pending_player: int = -1` (cloned).
  - `Action.Type` gains `CHOOSE`; `Action.choice: int = -1`; `static func choose(p: int, index: int) -> Action`; `Rules.validate` accepts CHOOSE only in CHOOSING for `pending_player` with a valid index; `Rules.apply` CHOOSE puts the card in hand (or `card_burned` if full), emits `dream_up_chosen {"player","card"}`, returns to MAIN. In CHOOSING every other action is "Choose a card first".
  - `CardDB.dream_up_pool(filter_kind: int, filter_land: int) -> Array[CardData]` (excludes NEUTRAL cards).
